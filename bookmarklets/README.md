# MOMENTUS 북마크릿 도구 (관리 규약)

> 북마크릿 = 설치 없이 "버튼 하나를 크롬 북마크바에 드래그"하면 끝나는 초경량 도구.
> 소스는 여기(momentus repo)에서 관리하고, 랜딩/배달 페이지는 `apps/<도구>/`에 둔다.
> 근거: 북마크릿은 가볍고 랜딩과 1:1로 짝지어지므로 무거운 독립앱(→ Seagate)과 달리 사이트 repo 안에서 관리하는 게 일관적. (전략: `docs/APEX_STRATEGY.md` §7 지그)

## 라인업 (4종, 전부 무료)

| 도구 | 파일 | 하는 일 | 상태 |
|---|---|---|---|
| 인스타 인기순 정렬 | `insta-rank.js` | 인스타 게시물을 좋아요순으로 재정렬 (레퍼런스 리서치) | 준비됨 |
| 유튜브 인기순 정렬 | `youtube-rank.js` | 검색·채널·쇼츠를 조회수순 정렬 | 준비됨 |
| 핀터레스트 원본 추출 | `pinterest-grab.js` | 저해상 썸네일 대신 originals 원본 URL 골라 일괄 복사 | 준비됨 |
| 퀵팡 (쿠팡 퀵보기) | `apps/quickpang/` (기존) | 상품 클릭 없이 옵션·품절 여부 즉시 확인 | 라이브 검증(1만 팔로워) |

## 소스 관리 규칙

1. **원본 소스 = 여기 `.js` 파일** (읽기 좋은/편집용). `javascript:` prefix 없이 순수 함수 본문.
2. **배포 산출물 = `javascript:` URL** — 빌드(minify + URL-encode)해서 `apps/<도구>/index.html`의 드래그 버튼 `href`에 주입.
3. **공용 스킨** — 4개 랜딩은 같은 컴포넌트(드래그 버튼 + FAQ + 귀환 갈고리 + 연관 도구 링크)를 공유. 스킨만 갈아끼움. (지그)
4. **귀환 갈고리 필수** — 각 도구 결과 UI 구석에 "⚡ 다른 무료 도구 보기 → the-moment.us" 삽입. QuickPang 교훈(1만 트래픽을 컨버전 못 함)의 해법.

## 계측 (2026-08-30 추가)

창업자 지적: *"쿠팡 북마크릿도 하는데 왜 핀터레스트·유튜브·인스타는 왜 안해?"*

### ★ 전용 속성 하나에 모은다 (2026-08-31 창업자 지시)

> "앞으로 생길 북마크릿을 고려해서 1개로 통합하고 그 안에서 들어온 소스가 뭔지 본다."

**무료 도구 (북마크릿)** — 속성 `460766131` / `G-T8Y89D206F`
(옛 이름 `Coupang Bookmarklet`. 쿠팡 전용처럼 보여서 바꿨다. 스트림도 `무료 도구 공용`.)

- **도구가 몇 개로 늘어도 속성은 이 하나.** 안에서 `tool` 로 가른다. 새 도구 = 이름 하나 추가.
- 가져감(`tool_install`)과 실행(`tool_run`)이 **같은 속성**이라 전환율이 한 화면에 있다.
- ⚠️ apex 로는 보내지 않는다 — 같은 사건이 두 속성에 **이중 계상**된다.

### 세 자리에서 잰다

| 자리 | 이벤트 | 어디로 | 4종 전부? |
|---|---|---|---|
| 랜딩 드래그 버튼 | `tool_install` (`method`: drag/click) | 무료 도구 속성 (`send_to`) | ✅ |
| 도구 실행 | `tool_run` (`tool`) | 무료 도구 속성 (픽셀 → 워커 → MP) | ❌ 인스타 제외 |
| 귀환 갈고리 | UTM 유입 | apex (랜딩 유입이므로) | ✅ |

⚠️ 랜딩의 `gtag('config', 'G-T8Y89D206F')` 에는 **반드시 `send_page_view:false`**.
   빼면 the-moment.us 전 페이지뷰가 도구 속성에도 쌓여 숫자가 못 쓰게 된다.

### 왜 도구 안에서는 4종을 다 못 재나 — CSP 실측

북마크릿은 **남의 페이지 안**에서 돌아 그 사이트 CSP 를 그대로 받는다.

| 사이트 | gtag.js | fetch | 이미지 픽셀 |
|---|---|---|---|
| 인스타그램 | ❌ | ❌ | ❌ |
| 핀터레스트 | ❌ | ❌ | ✅ (`img-src *`) |
| 유튜브·쿠팡 | ✅ (CSP 없음) | ✅ | ✅ |

셋의 **공통분모가 이미지**뿐이라 픽셀로 간다. 인스타는 어떤 방법으로도 불가 —
넣어 봐야 콘솔에 CSP violation 만 찍힌다(실측). 그래서 `insta-rank.txt` 에는 픽셀이 없다.

### 픽셀 경로

    도구 → https://the-moment.us/px.gif?t=<도구>&cid=<익명>&sid=<세션>
         → 워커(worker/naver.js) → GA4 측정 프로토콜 → apex 속성

- **비밀키를 북마크릿에 넣지 마라.** 소스는 랜딩에 그대로 노출된다 —
  키가 있으면 누구나 우리 속성에 가짜 이벤트를 넣을 수 있다.
  `GA_MP_SECRET` 은 워커 시크릿에만 있다.
- **보는 페이지 주소·제목·내용은 일절 보내지 않는다.** 남의 사이트에서 도는 코드라
  그걸 실어 보내면 우리가 열람 기록을 수집하는 게 된다. `referrerPolicy='no-referrer'`.
- 워커는 아는 도구 이름만 통과시킨다. 픽셀은 무엇이 오든 200 으로 답한다 —
  계측이 도구를 망가뜨리면 안 된다.

### ⚠️ `.txt` 를 고칠 때 금지 문자

- **`#`** — `javascript:` URL 에서 조각(fragment)으로 잘린다. CSS 선택자 대신 `getElementById`.
- **`%`** — 이 파일들은 퍼센트 인코딩돼 있어 디코드 때 깨진다.
- 한글은 `\u` 이스케이프로.
- 고친 뒤 반드시 **디코드해서 문법 검사**: `urllib.parse.unquote` → `node --check`.

### 맞춤 측정기준 (2026-08-31 등록 완료)

| 이름 | 매개변수 | 범위 |
|---|---|---|
| 도구 | `tool` | 이벤트 |
| 설치 방식 | `method` | 이벤트 |

⚠️ **등록 이전 데이터는 소급 적용되지 않는다.**
⚠️ 서비스계정은 읽기 전용이라 API 로는 못 만든다(403). GA 화면에서 만들어야 한다.

### ⚠️ 실시간 API 는 이벤트 범위 맞춤 측정기준을 지원하지 않는다

`customEvent:tool` 을 `runRealtimeReport` 에 넣으면 **"not a valid dimension"** 으로 죽는다.
**미등록이 아니라 API 제약이다** — 이걸 미등록 신호로 오해하지 마라.
등록 여부의 진실은 `properties/<id>/metadata` 다.
도구별 내역은 `runReport`(표준 보고서)로 본다. 수집 후 반영까지 몇 시간 걸린다.

확인기: `node scripts/ga_tools_report.mjs [--realtime]`
