## 0. 지금까지 합의된 것 (확정)

1. **본체를 "산출물 허브"로 만들지 않는다.** 로고 산출물은 이미 mark(mark.the-moment.us, Astro+CF Pages)가 전수 흡수(work 1,193건 + journal 매거진 74편 + RSS + 검색). 본체가 따로 담을 지속 스트림 없음. Reci는 아직 레포조차 없음.
2. **본체의 정당한 역할 = 퍼스널 브랜딩 + 제품 컨테이너 면(面).** 제품들이 서브도메인이라 apex를 비워둘 수 없음.
3. **카카오 등 네카라쿠베당토직야 corporate IA를 골격으로 빌리되, 메가코프 칸(IR·채용·ESG·신고센터)은 버리고, 카카오가 못 가지는 칸(얼굴·AI정체성·1인 경이)을 채운다.** "작은 카카오"가 아니라 "다른 종(種)".
4. **AI 시대엔 생산 장벽이 무너져 1인도 카카오급 완성도/구조를 만들 수 있다** — 야망을 줄이지 않는다. 단 카카오가 작동하는 건 *이미 5천만 청중*이 있어서지 페이지가 좋아서가 아님(= 페이지는 수요의 하류).

## 1. 최종 IA (모멘터스 본체)

```
the-moment.us  (corporate = 브랜드·신뢰 면)
├── 메인(/)        슬로건 "AI로 만드는 1인 스튜디오, 강형모" + 얼굴 + 제품 그리드 요약 + 정량 한 방
├── 소개(/about)   사람(강형모) + 일하는 방식(AI 생산엔진) + 연혁(만든 것 타임라인)
├── AI(/ai)        "어떻게 AI로 이걸 다 만드나" ← 서비스와 분리한 top-level (9사 공통 패턴=검증)
├── 서비스(/services)  제품 카드 그리드(mark·Reci·ChatPage…) → 각자 도메인 링크아웃 = 패밀리 셀렉터 겸
├── 소식(/log)     (선택·후순위) 만든 것·업데이트 changelog
├── [후순위] 브랜드/미디어킷 (로고 ZIP·컬러 스펙) — 협업·프레스 들어오면
└── footer        약관 · 개인정보처리방침(분리·강조) · 문의(hello@the-moment.us)
   드롭: IR · 채용 · ESG · 윤리/신고센터
거래 도메인(mark·Reci) footer → 사업자 풀 법정고지(상호 MOMENTUS·등록번호·통신판매업) + 환불규정
```

**중요 설계 원칙 (9사 공통 관행):** corporate=브랜드 신뢰, 서비스 도메인=법적 책임. 사업자 풀 법정고지는 *거래가 실제 일어나는 제품* footer에. apex footer엔 약관·개인정보·문의만 가볍게. apex를 "법무 페이지"로 오해 금지 — 브랜드 얼굴이다.

## 2. "나 대신 일하는 본체" 한 겹 (이번 세션 핵심 추가)

### 일 ①: 밖에서 LLM이 영업 (AEO)
- **⚠️ AEO 1순위 동력은 사이트 마크업이 아니라 "다출처 반복언급(corroboration)".** 4곳+ 노출 = 인용 2.8배. 무명의 문제는 권위 부족이 아니라 *합의의 부재*. → AEO 진짜 일은 페이지 *밖*에서, 메인 페이지는 그것들이 가리키는 **앵커**.
- **페이지에서 실제 효과 있는 것 딱 둘:**
  - 질문형 헤딩 + **40~60단어 원자 답변**(사람이 LLM에 묻는 그대로의 헤딩). Perplexity 추출 블록 크기.
  - **정량 + 날짜 사실**("2026-06 기준 1,193건, 평균 납기 14시간"). 매월 갱신 = 신선도+통계 무기.
  - **비교표 1개**("모멘터스 vs Looka vs Brandmark") = 인용 1위 포맷(21.9%).
- **미신(과투자 금지):** llms.txt(97% 트래픽 0, LLM 안 읽음 — 5분이면 까니 깔되 기대 0), 대형 스키마(ChatGPT 본문 인용엔 거의 무효, 구글 AI Overview·쇼핑엔만 강함), 백링크 사재기.

### 일 ②: 안에서 봇이 응대·전환 (전시→영업사원)
- **핵심: 새 AI 사지 말고, 이미 가진 slack-bot(Claude 페르소나 봇)을 사이트 위젯으로 노출.**
- TOP3 (자체 봇 전제, ROI 순):
  1. **온사이트 컨시어지/SDR** — 방문자와 대화→니즈·예산 자격검증→브리프 수집. "여기 보세요"가 "뭐 만들어드릴까요?"로.
  2. **리드 자동 적재** — 봇이 분류·점수·요약 → 형 슬랙엔 *바로 행동가능한 리드*만. (이미 inbox.md·라우드 분류하던 파이프라인 재사용)
  3. **자가 업데이트 산출물 섹션** — cron+빌드훅으로 최신 작업물·숫자 자동 갱신. "왜 업데이트해?"의 답.
- **함정(1인엔 독):** 전면 에이전틱 커머스·동적 UI 생성, SaaS SDR 구매(Intercom Fin·Qualified — 자체 봇 있는데 월과금 중복), KB 없는 deflection 봇(오답 자동발송=신뢰파괴).

### 페이지 밖, 형이 직접 할 AEO 엔진 (진짜 트래픽)
1. Reddit·LinkedIn·디스콰이엇·AI툴 디렉토리(Product Hunt 등) **4곳+에 동일 문구 시딩** = 인공 합의 제조
2. **Wikidata 엔티티 등재**(위키보다 문턱 낮고 LLM 그라운딩 직격)
3. **네이버 블로그/카페**(한국어 경로 별도)
4. 전부 같은 정량 사실을 **메인 페이지(앵커)로 링크**

# v2 갱신 (2026-07-08) — 방문자=주인공 리프레임

> v1은 "무엇을 담나(IA)·어떻게 발견되나(AEO)·누가 응대하나(봇)"를 정했다. v2는 **"들어온 사람을 어떻게 감동시켜 내 편으로 만드나"**를 정한다. 이건 랩 서비스 기획이 아니라 **소비심리 설계**다.

## 6. 큰 리프레임 — "도구가 영업하고, 허브는 회수한다"

v1의 결론("전시장 아님, 일하는 본체")은 유지. v2는 그 *작동 방식*을 못박는다.

**틀린 출발점(지금까지의 함정):** "나 이런 거 만들었어요(내 자랑) → 알아봐 주세요 → 북마크 해주세요." = 처음부터 *형*이 주어. 무명이 "날 알아줘"로 시작하면 아무도 안 온다.

**옳은 출발점:** 주어를 방문자로 바꾼다. 페이지는 형 얘기가 아니라 **그 사람이 원하던 것**으로 시작한다.

### 6대 원칙

1. **주인공은 방문자.** 모든 카피가 "이걸 만들었어요"가 아니라 "당신 이거 하고 싶었죠? 여기 됩니다."
2. **원초적 욕망에 말 건다.** 사람들이 진짜 원하는 건: 돈 벌고 싶다 / 릴스·인스타 해보고 싶다 / 근데 마케팅 도구가 비싸고 어렵고 모르겠다. 기능 설명이 아니라 **그 욕망의 언어**로.
3. **설명 말고 즉시 체험.** 북마크릿 모델 = 문턱 0(버튼 하나 드래그) → 클릭 → "어 진짜 되네" → "이렇게 간단해?" → "나도 될 것 같아." **제품이 곧 광고.** 기능 자랑·도구 원리 설명 아님.
4. **붙잡지 말고, 갈고리를 딸려 보낸다.** 떠나도 됨. 가져간 도구(북마크릿) 안에 **브랜드 귀환 버튼**을 심는다. 쓸 때마다 "아 이거 걔가 준 거" + "다른 도구 보기". 애원("한 번만 북마크 해주세요") 금지 — **효용으로 재흡입.**
5. **감동시키기 ≠ 기억시키기, 분리해서 푼다.** 먼저 도구로 감동(그 자체로 완결) → 기억은 갈고리가 알아서. 처음부터 "날 기억해"로 시작하니까 문제였다.
6. **AI 시대 = 작은 무료 도구 다작.** 생산 장벽이 무너졌으니 매력 표면을 많이 찍어낸다. 각 도구 = 야생에 흩뿌리는 미끼 + 귀환 갈고리. 허브는 그것들이 다시 모이는 우물.

### 체이닝 루프 (이게 엔진이다)

```
야생(인스타 검색결과 등)에서 "이거 필요했는데" 순간
  → 무료 도구 즉시 체험 → "진짜 되네" 감동
  → 도구에 박힌 귀환 갈고리("이거 준 곳 · 다른 도구 보기")
  → 허브 복귀 → "이 사람 이런 것도 만드네, 무료네, 재밌네"
  → 다른 도구로 연계 → 또 감동 → 또 흡입
  → 반복 = 단골(팬)
```

## 7. 지그(jig) — 재사용 한 벌 (형이 오늘 격상시킨 핵심)

사이트의 심장은 페이지가 아니라 **"제품 하나 = 필드 채우기"가 되는 틀**이다.

- **단일 매니페스트**(예: `products.json`)가 진실의 원천. 항목 = `{이름, 원초-욕망 한줄카피, 무료여부, 도구타입(북마크릿/앱/서비스), url, 썸네일, 귀환-갈고리 설정}`.
- 지그가 이 매니페스트를 읽어 **자동 생성**: /services 그리드 · 각 미니 랜딩 · sitemap · **법정 footer(개인정보·약관)** · 문의창구 · 봇 컨텍스트 · 각 도구에 붙일 귀환 갈고리.
- **새 제품 = 매니페스트에 한 줄 추가 = 전 채널 자동 반영.** "끼워만 놓으면 다음 것도 이어감"의 실체. 개인정보처리방침·약관·문의도 한 벌 만들어 돌려쓴다.

## 8. 랜딩이 라인업을 소화하는 법 (소비심리 IA)

- **히어로 = 방문자 욕망 질문으로 시작.** "강형모입니다"❌ → "인스타로 뭐 좀 해보고 싶은데, 도구가 비싸고 어렵죠?"⭕ → 바로 아래 **무료로 지금 되는 것 1개 즉시 체험**(북마크릿 드래그 데모).
- **라인업 정렬 = 카테고리가 아니라 "당신이 하려는 일"별.** (돈 벌기 / 인스타·릴스 / 로고·브랜딩 / 자동화). 형이 만든 북마크릿의 "인기순 정렬" 철학을 사이트 IA에도 적용 — 방문자 기준 정렬.
- **각 카드 = 기능명❌, "되는 결과 + 무료 배지 + 지금 써보기"⭕.**
- **사람(매력) 층은 뒤에.** 도구로 먼저 감동시킨 뒤 "이거 다 만든 사람 누구야?" 궁금해질 때 /about 등장. SNS·소통 센스·"이 사람 재밌네"는 여기서.

## 9. v2 빌드 순서 (저 트래픽 현실 반영 — 트래픽 0에서도 이득 나는 것부터)

| 순위 | 무엇 | 왜 지금 |
|---|---|---|
| 1 | **지그 + 매니페스트 + 귀환 갈고리 규격** | 방문자 0이어도 형 시간을 아낌 = 무조건 남는 장사 |
| 2 | **첫 미끼 배포**: 이미 있는 북마크릿(인스타 인기순 정렬)에 갈고리 장착 → 히어로 즉시체험으로 | 즉효 무료 도구 = 감동 훅 1호 |
| 3 | **AEO 앵커**(히어로 정량 + 엔티티 한 줄) | 사람 안 와도 LLM이 인용 |
| 4 | 매니페스트에 기존 제품 편입(mark·ChatPage·플래너 무료 미끼) + 인격/매력 층 | 방문자 생기기 시작하면 팬 전환 |
| 5 | 봇 위젯 → 도구 다작 라인 가동(지그로 매주 작은 무료 도구 흩뿌리기) | 트래픽 부스터 |
