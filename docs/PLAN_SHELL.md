## 0. 이 계획의 전제 3개

1. **폴더를 모으지 않는다.** 공용화는 저장소를 합치는 일이 아니라, `momentus` 안에 **파일 2개**(`shell.js` · 확장된 `products.json`)를 만들고 각 제품이 **스크립트 한 줄**을 붙이는 일이다. `planner-factory`·`mark`·`cue`·`kontext`는 지금 위치·지금 구조 그대로 둔다.
2. **notes 작업을 멈추지 않는다.** 지금 유일하게 매출에 붙어 있는 라인이다. 껍데기 작업은 제품 **밖에서** 만들어 나중에 한 줄로 붙이므로 병행 가능하다.
3. **각 제품이 부담할 총량 = 스크립트 한 줄 + `feed.json` 한 개.** 제품당 30분 이하. 이 이상 제품 코드를 건드리는 설계면 잘못된 설계다.

### ⚠️ Phase 1에서 터진 것 = 가드 룰 2개 (재발 방지)

**① 공용 바의 클래스 이름은 반드시 `mmt-` 접두어.**
notes 상세페이지가 주입하는 `ds.css`에 **전역 `.wm`**(워터마크: `position:absolute; font-size:170px; opacity:.07`)이 있어서 바의 워드마크를 덮어 레이아웃이 깨졌다. 스토어의 CSS 재스코프는 `:root`·`html`·`body`·`*`만 다시 쓰고 **클래스 선택자는 전역으로 남긴다** — 그래서 `.in`·`.wm`·`.it` 같은 일반 이름은 언제든 충돌한다.
→ **규칙: `#mmt-bar` 안의 모든 클래스는 `mmt-` 접두어. 요소 선택자(`nav`,`a`)에 기대지 않는다.**

**② `--mmt-bar-h`는 바를 실제로 붙인 뒤에만 세운다.**
삽입 전에 세웠더니, 바 렌더가 실패했을 때 제품 헤더만 40px 내려가 **빈 띠**가 남았다. fail-open은 "바만 없고 나머지는 원래대로"여야 한다.

**③ 문자열 일괄 치환으로 JS를 건드리지 말 것.** `.sep` → `.mmt-sep` 치환이 `it.sep`까지 먹어 `it.mmt-sep`(ReferenceError)가 됐다. 바가 통째로 안 그려졌지만 **fail-open 덕분에 제품 페이지는 무사했다**(설계가 제 값을 했다).
→ 이후 `gen_site.py`는 생성된 `shell.js`를 **헤드리스로 한 번 렌더**해 항목 수·활성표시를 검사한 뒤 배포한다.

**④ 스크롤하면 제품 고정헤더가 바를 따라 올라와야 한다.** 바는 흐름 안에 있어 밀려 나가는데 제품 헤더는 `top:40px`에 고정돼 내용 위에 떴다. → `shell.js`가 `--mmt-bar-h`를 `max(0, H - scrollY)`로 rAF 갱신. 제품은 CSS 한 줄 그대로 따라온다(제품 코드 변경 0).

### 그리드 규칙 — 바는 제품 그리드에 **맞추지 않는다** (실측 근거)

바(20px 여백)와 notes 로고(56px 거터)가 16px 어긋나 실수처럼 보인다는 지적이 나왔다. **애플을 직접 측정해 판단했다.**

| `apple.com/kr/mac` · 1280px | 좌측 X |
|---|---|
| 글로벌 바(애플 로고·메뉴) | **142px** (996px 중앙 컨테이너) |
| 페이지 콘텐츠(`Mac` 헤드라인·제품 타일) | **80px** |

→ **62px 어긋나 있다. 애플도 정렬하지 않는다.**

**규칙**: 브랜드 바는 콘텐츠가 아니라 **크롬(chrome) 층**이다. 전 사이트 공통 **고정 20px 여백**(모바일 16px)을 쓰고 제품 그리드를 따라가지 않는다.
- 이유 ①: 제품마다 최대폭·거터가 달라(notes 1400/56 · apex 1200/40 · mark·cue 각각) **맞추려 들면 어느 하나엔 반드시 어긋난다.**
- 이유 ②: **'살짝 어긋남'이 실수로 읽힌다.** 확실히 다른 층으로 보이면 눈이 문제 삼지 않는다(어두운 띠 + 13px 작은 타이포 + 40px 낮은 높이가 그 신호).
- 워드마크는 **왼쪽 유지**. 브랜드 앵커이자 귀환 통로라 시선이 시작하는 자리에 둔다. (구글이 오른쪽에 두는 건 브랜드가 아니라 *계정* 칩이다.)
- 훗날 특정 제품에서 굳이 맞추고 싶으면 `--mmt-gutter` 를 선언하게 하는 옵트인을 열 수 있다. **기본은 맞추지 않는 것.**

**게이트 결과**: 4개 화면 + 모바일 통과. **나머지 제품은 복붙이다.**

### 2.6 — 공용 디자인 토큰 배급 (중앙 통제) ✅ 라이브

규격을 "각자 같은 숫자를 적어두는" 방식으로 두면 곧 다시 갈라진다. **`shell.js`가 `:root`에 토큰을 내려주고, 제품은 `var(--mmt-*, 자기값)` 폴백으로 쓴다.** 이제 momentus에서 숫자 하나를 고치면 세 제품이 동시에 따라오고, 스크립트가 못 떠도 폴백이 원래 모습을 지킨다(fail-open 유지).

```
--mmt-gut  clamp(20px,4vw,56px)   --mmt-maxw 1320px    --mmt-bar2-h 64px
--mmt-fs-logo 22px   --mmt-fs-nav 14px   --mmt-fw-nav 600   --mmt-nav-gap 26px
--mmt-fs-cta 14px    --mmt-cta-pad 9px 18px   --mmt-cta-r 999px
```

**⚠️ 앞선 판단 하나를 뒤집었다.** "2단 거터는 제품 자기 것" 이라고 적었는데, 그 결과 **로고 좌표가 notes 56 / cue 48 / mark 64로 갈렸다.** 제품을 오갈 때 로고가 튀는 게 더 큰 문제라 **헤더 컨테이너만 공용 거터**를 쓰게 바꿨다(본문 그리드는 여전히 제품 것). 실측: 세 사이트 모두 **로고 left = 51px** 로 일치.

**같이 정리한 불일치 3건**
| 무엇 | 전 | 후 |
|---|---|---|
| mark 헤더 밑줄 | `border-bottom` 있음(혼자만) | 제거 |
| notes CTA | 흰 스트로크 | **채움 pill**(잉크) — mark·cue와 같은 문법 |
| notes 헤더 배경 | 투명 + `mix-blend-mode: difference` | 반투명 흰 + 블러 |

> `mix-blend-mode`는 **채움 CTA와 원리상 양립 불가**다. 배경색을 반전시키는 트릭이라 검은 pill이 흰 배경 위에서 흰색으로 반전돼 사라진다. 그래서 폐기하고 mark·cue와 같은 반투명 흰 배경으로 갔다.

### 2.7 — 본문 타이포·페이지 컨테이너까지 통일 ✅ 라이브

**폰트는 이미 셋 다 Pretendard였다.** 갈렸던 건 크기·행간·자간이었다.

추가 토큰: `--mmt-fs-base·lh-base·ls-base · fs-lead·lh-lead · fs-sm · fs-h3 · fs-h2 · lh-head · ls-head`
**히어로·디스플레이 크기는 건드리지 않았다** — 제품 브랜드 목소리다.

**페이지 컨테이너도 같은 토큰으로 묶었다.** 헤더만 공용 거터를 쓰니 notes에서 로고(51)와 본문(56)이 **5px 어긋났고**, 그건 스스로 세운 규칙("살짝 어긋남이 제일 나쁘다")에 걸린다. `.wrap`/`--gut`/`--maxw`를 전부 `var(--mmt-*, 제품값)`으로.

### 2.8 — ⚠️ 런타임 주입 폐기, **소스에 박는 방식**으로 전환 ✅ 라이브 (구조 변경)

**사장님 지적**: "스크립트가 로딩되면서 강제로 만들고 깜빡하면서 보정하는 느낌" — 맞는 지적이었고 원인이 둘이었다.

1. `shell.js`가 **나중에** 토큰을 덮어써서, 첫 페인트는 제품 원래 값(예: 행간 1.65)으로 그려진 뒤 공용 값(1.6)으로 바뀌었다 → 깜빡임.
2. 바를 **JS로 끼워 넣어** 페이지가 40px 밀렸다 → 레이아웃 시프트.

**전환한 구조**
```
정본:  momentus/scripts/gen_site.py  (SHELL_TOKENS · SHELL_BAR_CSS · shell_bar_markup)
반영:  momentus/scripts/sync_shell.py → 제품 소스의 MMT:BEGIN/END 마커 사이에 써넣는다
결과:  런타임 보정 0 · 깜빡임 0 · 외부 의존 0 (제품 HTML/CSS 안에 실값이 박힘)
```

- 각 제품에서 **`<script src=shell.js>` 참조를 전부 제거**했다. 바 마크업과 토큰 실값이 소스에 있다.
- **notes 헤더 `fixed` → `sticky`**. 바가 흐름 안에 있으니 JS 스크롤 보정(`--mmt-bar-h` rAF 갱신)이 필요 없어졌다 — 그 코드도 함께 사라졌다.
- 활성 표시도 도메인별로 **빌드 시점에 박는다**(`aria-current`), 런타임 판정 없음.

**바꾸는 법**: `gen_site.py`의 `SHELL_TOKENS` 수정 → `python3 scripts/sync_shell.py` → 각 제품 저장소 커밋·배포.
자동 반영은 잃었지만(제품 재배포 필요), 애플·어도비도 글로벌 바를 각 자산에 빌드 타임으로 굽는다.

**실측(라이브)**: 세 제품 모두 `바=HTML에 박힘 · shell.js 참조=0개 · 본문 16px/25.6px · 로고 left=51 · 활성표시 정상`.

⚠️ **작업 중 사고 1건**: 동기화 스크립트가 CSS 블록을 `shop_ui.js` **맨 앞**에 넣어 JS 파일이 깨졌다(앵커 정규식 `^`가 0번째에 매치). `.css`는 파일 맨 앞, HTML/JS 템플릿은 `<style>` 뒤로 앵커를 분기해 수정.

적용: `momentus@abed027` · `planner-factory@7d23c45` · `cue@f5fbcbc` · `mark@a8087e5`

## 4. Phase 3 — 블로그 승격 ✅ **완료 · 라이브** (2026-07-27, `momentus@e42da98`)

### ⚠️ 계획 하나를 바로잡았다 — "mark 엔진 승격"은 불가능했다

mark 저널은 **Astro Content Collections**, apex는 **파이썬 정적 생성기**다. 엔진을 옮기는 건 승격이 아니라 재작성이다. 대신 가져온 것은 **콘텐츠 모델**(파일 + frontmatter + 태그)이고, 그게 실제로 필요한 전부였다.

### 진짜 문제는 따로 있었다
apex 글 3편이 **`gen_site.py` 안에 파이썬 dict로 박혀 있었다.** 글 하나 쓰려면 1,800줄짜리 생성기를 고쳐야 했다.

→ **`content/stories/<slug>.html`** (frontmatter + 본문 HTML)로 분리. **새 글 = 파일 하나 추가.** 생성기는 손대지 않는다.

```
---
title: 왜 공짜로 푸는가
sub: 돈을 받을 이유가 없는 건 그냥 드립니다.
cat: 관점
date: 2026-07-05
mins: 4
tags: 무료 도구, 사람
---
<p>본문 HTML…</p>
```

### 만든 것
| 무엇 | 주소 |
|---|---|
| 이야기 인덱스(태그 칩 필터) | `/stories/` |
| 글 | `/stories/<slug>/` |
| **태그별 정적 페이지**(매니페스트 파생) | `/stories/tag/<key>/` — theplan·mark·cue·heyreci·kontext·tools·people |
| RSS | `/stories/rss.xml` |
| 옛 주소 회수 | `/log/*` → 301 |

- **URL은 `/stories/`(영문=SEO), 화면 라벨은 `이야기`(한글=voice)** — `INFORMATION_ARCHITECTURE.md` §A 원칙 그대로.
- **태그 축은 매니페스트에서 파생**한다. 새 제품이 `products.json`에 추가되면 태그와 태그 페이지가 자동으로 생긴다.
- 스트림에는 글 + 유튜브 영상이 **같은 시간축**으로 섞인다(§10 '한 스트림'의 1차 구현).

⚠️ **실측 함정**: `_redirects`에 `/log/*` 와일드카드를 두니 **개별 글 규칙을 덮어** 전부 목록으로 보냈다(`/log/why-free/` → `/stories/`). 와일드카드를 빼고 정확 경로만 남겨 해결.

### 일부러 미룬 것 — 제품 2단 바의 '이야기' 재조준

착지점(`/stories/tag/<key>/`)은 만들어 뒀지만 **제품 메뉴는 아직 각자 자기 블로그를 본다.** 지금 공용 블로그는 3편이고 mark는 84편, cue도 자체 `/blog`가 있다 — 지금 돌리면 **방문자를 3편짜리 페이지로 보내는 다운그레이드**다.

**전환 조건**: 해당 태그에 글이 5편 이상 쌓이면 그 제품의 2단 바 '이야기'를 `/stories/tag/<key>/`로 돌린다. (라벨은 이미 셋 다 `이야기`로 통일해 뒀으니 링크만 바꾸면 된다.)
